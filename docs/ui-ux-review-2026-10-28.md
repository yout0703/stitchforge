# StitchForge UI / UX 优化与验收（2026-10-28）

参考：[如何用 AI 优化现有产品的 UI 与 UX](https://www.oiloil.org/articles/ai-optimize-existing-product-ui-ux)。采用沿用既有设计规范、控制改动边界、保存原版与优化后对比、走查实际任务的方式。保留现有蓝白工作台、品牌与图片素材，在本轮开始时已有的未提交修改上增量调整。

## 发现与处理

| 步骤 | 本轮观察 | 调整与验证结果 |
| --- | --- | --- |
| 1. 登录 | 809px 下左栏被表单挤压，标题断成多行；手机需越过展示图片才能登录 | 调整双栏比例、字号、背景与阴影；手机隐藏大图，表单直接出现在首屏；密码可显示或隐藏。已验证 |
| 2. 首次打开图纸库 | 空状态只提示“从左侧上传”，但平板没有左侧导航 | 在空状态直接加入图片生成、OXS / XSD 导入及空白绘制按钮，并解释计次方式。已验证导入弹窗与空白创建 |
| 3. 新建 | 导航在 900px 切换，状态与弹层样式却在 620px 切换，导致 621–900px 点击新建无可见菜单 | 将状态、创建菜单、线色抽屉统一到 900px；弹层背景 inert、焦点限制、Esc 关闭后恢复到新建按钮。809px 实测通过 |
| 4. 找到并打开图纸 | 卡片单击只选中，打开需要详情按钮或双击 | 保留详情选择和双击，并在每张卡片提供明确的打开按钮；修正未经实现的“记录绣制进度”文案。直接打开通过；列表改为两行元数据，四张卡片的日期与打开按钮均无重叠 |
| 5. 查线色 | 长色表需手动查找，针数散在文字中 | 独立色表组件，支持色号、品牌、名称和符号搜索、按针数降序；针数右对齐；空结果可以恢复；切换项目清空搜索。30 色图纸检索、高亮与排序通过 |
| 6. 编辑与保存 | 退出编辑后即使有修改，保存入口也消失；下载与保存争用主按钮 | 未保存时在看图模式继续显示保存按钮；标题显示保存状态；下载采用次按钮。键盘绘制两针、退出编辑、保存成功已验证 |
| 7. 看图与下载 | 图纸规格区展示了不直接帮助绣制的算法字段；窄桌面工具栏文字挤压 | 规格与线色来源折叠，移除固定显示的算法字段；调整 901–1180px 栅格和工具栏；手机隐藏重复模式说明。390px 看图与 OXS 文件准备成功 |

## 验证

- `pnpm --dir apps/web check`：9 个测试文件、48 项测试通过；类型检查及生产构建通过。
- Oxlint 没有错误；仍有本轮之前已经存在的 3 条 `set-state-in-effect` 警告，位于 `useGeneration`、`PatternCanvas` 和生成成功后的 App 状态处理。
- Codex 内置浏览器，实际测试 390 × 844、809 × 954、901 × 900、1440 × 1000。
- 390px 看图画布为 390 × 608，页面宽度为 390px，无横向页面溢出。901px 编辑画布宽 369px，线色栏完整留在视口内。
- 走查：空状态入口、创建菜单、Esc 与焦点返回、空白创建、键盘绘制、退出编辑后保存、卡片直接打开、色号检索、无结果恢复、按针数排序、选色高亮、手机抽屉、下载弹窗、OXS 准备成功、刷新恢复。
- 预览测试数据存放于 `/tmp/stitchforge-ui-ux-20261028`。示例图纸复用项目已有输出，未修改用户图纸。
- 未运行付费图片生成，未验证真实手机软键盘、实体设备手势、Pattern Maker / Saga 导入或完整无障碍合规。

## 维护约定

- 900px 是侧栏切换为底部导航、创建菜单与线色抽屉的共同断点；620px 只用于更紧凑的手机排版。
- 搜索结果是当前色表的派生数据，不另存一份结果状态；`ThreadPalette` 使用项目 ID 作为 key，切换项目时重置查询与排序。
- 有未保存修改时，保存入口不受查看 / 编辑模式切换影响。查看状态与账号保存状态分别表达。
- 新增颜色、背景、边框与状态样式沿用 `index.css` 的 `--sf-*` 令牌；不引入新 UI 框架或依赖。
