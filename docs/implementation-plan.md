## 3. 第一轮研发应交付什么

第一轮只完成 T01–T05 的最小垂直路径，输出可以检查的本地文件，不先搭建完整账号系统或营销页面。

1. 导入仓库中的 4×3 手工样例，通过 Schema 与语义校验。
2. 输出精确针数、留空、连通域和物理尺寸。
3. 生成预览、彩色及黑白 PDF，图纸可以辨认黑线、白线与空格。
4. 写出 `.stitchforge` 并重新打开，设计内容和规范哈希相同。
5. 追加 160×240 的人工分页样例，独立检查页映射并打印选页。

同时落实字体和最小真实材料来源。若真实色库暂未解决，继续使用标记清楚的 TEST 夹具完成结构与版式，不把它用于真实线色匹配演示。

## 5. 持久性与输入故障测试

| 故障注入 | 验收结果 |
|---|---|
| 任务入库后进程退出 | 重启后可领取，输入版本不丢失 |
| 文件写完、数据库提交前崩溃 | 文件成为孤儿；无半成品引用，后续可回收 |
| 数据库登记成功后客户端超时重试 | 相同幂等键返回相同版本／任务 |
| 租约过期后旧 worker 返回 | fencing 条件阻止提交旧结果 |
| 取消计算或删除项目后模型返回 | 结果不更新项目、不创建可下载发布 |
| PDF 成功但工程文件／材料表生成失败 | Release 为 FAILED，不拿历史文件填充 |
| 交付生成期间用户继续编辑 | 包始终使用固定 revision，界面显示正在打包哪个版本 |
| 原图过大、解码炸弹、ZIP 越界或 XML 外部实体 | 解析前／中明确拒绝，无外部网络读取及任意文件访问 |
| 本机页面遭不允许的跨站请求 | 不能读取或修改工程 |
| 从备份恢复到空目录 | 可打开指定旧版本，交付文件哈希全量一致 |

这些检查针对真实数据损坏风险；实现时不把测试写成简单重复私有函数细节。

## 6. 性能与资源目标

以下均为待测目标。基准机建议选一台 16 GB 内存、无独立 GPU 的开发电脑，记录 CPU、系统、浏览器、依赖锁文件和电源模式；不同硬件的结果不混为同一 P95。每项运行至少 30 次，冷／热启动分别统计。

| 场景 | 目标 |
|---|---|
| 300×300／64 配方加载到可编辑 | 热启动 P95≤2 秒，本地 API，不含下载原图 |
| 平移缩放与当前选区 | 常规视口帧耗时 P95≤33 ms，无全画布 DOM 针格 |
| 单次画笔可见响应 | P95≤50 ms；持久化确认 P95≤300 ms，最多 5,000 格命令 |
| 完整结构校验＋统计 | P95≤1 秒，90,000 格 |
| 8 MP 图到 300×300／24 色单候选 | P95≤30 秒，CPU 模式，不含外部模型 |
| 普通 PDF 导出 | 300×300、默认约 20 张图纸页，P95≤30 秒 |
| 取消请求 | 可中断阶段 2 秒内响应；阻塞子进程 10 秒内终止 |
| 任务资源 | 默认单重型任务；worker 峰值 RSS 目标≤1 GiB，超限明确失败 |
| 阶段超时 | 确定性阶段默认 120 秒；模型请求默认 90 秒，可按 provider 配置 |

40 MP 输入上限不承诺在上述 8 MP 基准时延内。色差计算必须分块，避免构建网格×全色库×多中间数组耗尽内存。若达不到目标，先通过采样、视口裁剪和缓存测量定位，调整产品上限需要记录设计变更，不能把未测指标写成现有性能。

## 8. 实绣与 AI 评测

建立至少 12 幅经过授权的原图回归集，覆盖插画、宠物、人物、文字、渐变、复杂背景、大留白和细线；每幅标记必须保留的区域和可简化区域。至少三幅选择代表区域进行实际试绣，其中包含孤立高光、色阶边界和透明留白。

试绣记录图纸版本、裁片区域、布 CT、实际线号和股数、正背面照片、绣制与返工时间、材料消耗方式、读图歧义和修改建议。局部试绣证据必须标明区域，不扩展宣称整幅实绣通过。

AI 对照采用同一图片、同一网格／预算以及同等评审要求，比较 M1 确定性与 M2 辅助结果；随机化评审顺序，分开统计熟悉度和题材。主要指标是达到用户认可所需的人工修改分钟数、命令数、修改针格比例和关键细节失败数。

M2 的初始升级目标是：硬规则通过率 100%、锁定违反为 0；对照集人工修改时间中位数至少减少 20%，且关键细节失败数不增加。20% 是待验证产品目标，小样本只能支持本回归集上的结论。若未达到，保留为实验辅助功能，不能以另一个模型的主观打分替代证据。

耗线与工时区间在 T18 使用独立留出的样本检查覆盖率和误差。校准样本不足时继续显示缺省状态，不用更精细的小数造成准确的错觉。
