## 1. 项目定位与产品边界

### 1.1 项目目标

构建一个 AI 辅助十字绣设计引擎：用户上传照片、插画或其他图片后，系统分析主体与次要背景，结合目标尺寸、绣布、颜色预算和操作难度，将画面转换为可实际手工绣制的针脚设计，并交付可阅读、可打印、可编辑的图纸。

同时逐步支持两类逆向能力：从已有图纸恢复结构化针脚；根据绣成品照片或刺绣效果图重新打版。

### 1.2 不是“图片转像素画”

普通图片转换只需要追求缩小后的视觉相似；本项目还必须满足材料、针法、坐标、图例、操作负担和输出兼容约束。

主要目标包括：

- 主体仍然可辨识，关键表情、轮廓与构图不被错误简化。
- 每一针都明确对应位置、针法、真实用线和股数。
- 图纸与效果预览一致，不存在只在效果图中出现的细节。
- 可以人工修正、撤销、锁定区域和追踪版本。
- 图纸可读、材料可采购、导出结果可校验。

### 1.3 产品边界

| 能力 | 定义 | 承诺边界 |
|---|---|---|
| 图片正向打版 | 从普通图片重新设计针脚 | 生成可操作的设计，不保证像素级还原原图 |
| 结构化图纸转换 | 解析 OXS 等已有针脚数据 | 仅对已支持并验证的功能承诺保留 |
| PDF／扫描图纸恢复 | 恢复网格、符号、图例和针法 | 输出识别置信度，未确认内容不得静默发布 |
| 成品参考重建 | 根据成品照片或 AI 效果图再设计 | 不保证恢复原始线号、尺寸或唯一原图纸 |
| 刺绣风格展示图 | 可选的宣传或场景展示 | 不能代替针脚数据预览或成为可绣性依据 |

首期目标是“看图数格绣”。直接印到绣布上的印花生产涉及布格配准和打印定位，应作为独立的生产能力设计。

## 2. 十字绣领域知识

本章区分领域事实与项目建模建议。资料来源编号见文末。

### 2.1 图纸的基本组成

常见图纸通过网格与格内符号表示针脚和用线，并使用较粗的 10×10 网格线辅助计数。彩色符号图和黑白符号图都可以作为阅读形式；线号图例用于解释符号含义。[S01]

真实图纸可能同时包含全针、勾边和法国结，并分别说明股数。Stitched Modern 的示例 PDF 展示了这种多针法交付形式。[S02]

因此，一份完整设计不能仅用“二维 RGB 图片”表示。

### 2.2 针法及几何语义

DMC 的图纸阅读资料介绍了全针、勾边、半针、四分之一针与四分之三针等表示方式；勾边用于轮廓等线条表现。[S03] 法国结常以圆点标识，具体做法仍以该图纸图例与说明为准。[S01]

| 针法 | 几何含义 | 建议记录字段 | 产品阶段 |
|---|---|---|---|
| 全针 Full Cross | 一个完整的 X | 格子坐标、用线配方、上下覆盖方向 | MVP |
| 半针 Half Cross | 一条完整对角线 | 格子坐标、对角方向、用线配方 | 后续 |
| 1/4 针 Quarter Stitch | 格子角点至中心的一段斜线 | 格子、所在角、方向、用线配方 | 后续 |
| 3/4 针 Three-quarter Stitch | 半针与一个四分之一针组合 | 两部分的方向与组合关系、用线配方 | 后续 |
| 勾边 Backstitch | 两个落针点之间的线段 | 起终点、用线配方、线段关系 | 优先扩展 |
| 法国结 French Knot | 指定位置的结点 | 坐标、用线配方、做法说明 | 后续 |
| 珠绣等装饰 | 指定位置的附加材料 | 位置、材料规格、数量、方向 | 后续 |

建模注意事项：

1. 图纸中的“★”等符号通常是用线标识，不意味着实际绣一个星形。
2. 线条图层需要真实落针点，不能只保存视觉上好看的曲线。
3. 分数针需要方向与几何信息，单独保存“3/4”不足以还原其形状。
4. 绘制时可以表达某个坐标，不代表它一定适合所选绣布；材料适配仍需规则与实绣验证。
5. 不同针法应分开计数。全针数、勾边段数和法国结数不宜混为一个不加说明的“总针数”。

### 2.3 绣布、CT、网格尺寸与实际尺寸

对 Aida 布，CT 表示每英寸可绣的格数。同一网格下，CT 越高，作品的物理尺寸越小；其他均匀织物还可能采用跨两根经纬线的 over two 绣法。[S04]

对 API 和计算引擎，建议区分以下变量：

| 字段 | 含义 |
|---|---|
| `fabric_type` | Aida 或其他绣布类型 |
| `fabric_count` | 布的标称密度及其单位语义 |
| `worked_over` | 在适用的织物计数体系下跨几根布线 |
| `effective_stitches_per_inch` | 换算完成的有效每英寸针数 |
| `width_cells` / `height_cells` | 图案横纵网格数 |
| `strands` | 使用的绣线股数，不是跨布线数量 |
| `margin_cm` | 裁布相对绣制区域的留边 |

计算应使用有效每英寸针数：

```text
绣制宽度（cm）= 横向格数 / 有效每英寸针数 × 2.54
绣制高度（cm）= 纵向格数 / 有效每英寸针数 × 2.54
裁布宽度（cm）= 绣制宽度 + 左留边 + 右留边
裁布高度（cm）= 绣制高度 + 上留边 + 下留边
```

示例：160×240 格，14CT Aida，每格一个全针：

```text
绣制尺寸约为 29.0 × 43.5 cm。
若每边留 5 cm，裁布尺寸约为 39.0 × 53.5 cm。
```

其中留边只是配置示例，应依据装裱方式确定；原始数值应在内部保留精度，展示时再四舍五入。

**重要区别：提高 CT 不会给同一份 160×240 图纸增加细节。增加细节通常需要增加网格数、改变构图或采用其他针法。**

系统还应分别保存“设计画布尺寸”和“实际有针脚的包围区域”，避免透明留白导致尺寸说明混乱。

### 2.4 实际绣线、屏幕颜色与图纸符号

三者必须分离：

```text
真实绣线身份 → 屏幕近似颜色 → 图纸符号
```

真实绣线建议使用 `品牌 + 系列 + 线号` 标识；线号使用字符串，不仅支持纯整数。

| 概念 | 含义 | 不应混淆的对象 |
|---|---|---|
| 材料身份 | 可实际采购的绣线 | 任意 RGB／HEX |
| 屏幕色值 | 展示或匹配计算的近似值 | 实体线样的完整视觉效果 |
| 图纸符号 | 图例中的用线标识 | 实际针形 |
| 用线配方 | 某种用线组合及股数 | 单独一个品牌线号 |
| 绣布底色 | 未覆盖区域的材料颜色 | 白线或其他绣线 |

DMC 提供带实体绣线样本的色卡。[S05] 生产级色库应保存资料来源和版本，并进行实体线样校验，不应把网上 RGB 表直接标记为“官方校准色库”。

建议的色库元数据包括：来源、采集日期、授权状态、颜色空间、测量条件（如有）、显示近似值及校准状态。无法确认的测量条件不能补造。

### 2.5 留空、白线、混线与股数

- **留空不等于白线。** 即使白布上的视觉效果接近，材料用量与针数也不同。
- **混线必须保留组成。** “A 线号一股 + B 线号一股”是配方，不能仅以两个 RGB 的平均值替代。
- **同一线号可以有不同配方。** 全针用两股、勾边用一股，应分别记录。
- **混线与覆盖效果需验证。** 首期不承诺仅靠屏幕颜色计算即可预测真实混线效果。

## 3. 最终交付物与文件格式

### 3.1 推荐的作品包

| 交付物 | 必要信息 |
|---|---|
| 作品说明 | 名称、网格尺寸、绣布、CT、有效针数密度、股数、绣制尺寸、裁布留边 |
| 针脚数据预览 | 由真实针脚生成的图案、绣布底色、覆盖范围 |
| 彩色符号图 | 色块、符号、网格、坐标、中心定位 |
| 黑白符号图 | 不依赖颜色辨认的符号、清晰网格和图例 |
| 分页放大图 | 页码、页面拼接关系、全局坐标、明确的重叠区 |
| 材料表 | 品牌、系列、线号、配方、符号、针法、数量与用量估算 |
| 可编辑工程 | 完整针脚、设计参数、版本与编辑状态 |
| 交换文件 | 经验证的 OXS 或其他支持格式 |

材料表中的用量和完成时间初期应标注为估算，并说明适用假设；不能仅凭针数给出无误差的承诺。

### 3.2 文件格式分层

OXS 的提出用于解决不同软件图纸格式之间的交换问题，但它不是所有软件都完整遵守的统一行业标准。[S06]

| 格式 | 主要作用 | 项目策略 |
|---|---|---|
| PNG／JPEG | 预览、分享、图纸图片展示 | 不作为唯一主数据 |
| 普通 PDF | 打印与人工阅读 | MVP 必须支持 |
| Pattern Keeper 目标 PDF | 按目标阅读软件要求组织的 PDF | 独立导出配置，独立实测 |
| OXS | 结构化十字绣数据交换 | 优先导入与导出 |
| XSD／PAT／XSP／SAGA／CSS | 不同软件生态的格式 | 依据规范可得性和用户需求逐项适配 |
| 自有工程文件 | 保存完整设计与编辑状态 | 作为内部主格式 |

图纸软件开发者的兼容列表列出了 Pattern Maker 的 XSD、PCStitch 的 PAT、Cross Stitch Professional 的 XSP，以及 Cross Stitch Saga 的 SAGA/CSS 等格式。[S09] 这里的 XSD 是图纸文件格式，不是 XML Schema 的通用含义。

### 3.3 PDF 与阅读软件兼容性

Pattern Keeper 官方的特定软件导出说明涉及可作为文本选择的 TrueType 符号、页面尺寸、图例标题和预览页设置。[S08]

由此应区分两个验收目标：

```text
人工可以阅读和打印。
目标应用可以正确识别网格、符号和图例。
```

将整个图纸栅格化、将符号转为图片或改变图例布局，都不能默认仍然满足机器识别要求。具体针法与布局支持要按目标软件和版本验证。

### 3.4 OXS 与 Saga 的兼容边界

OXS 公开规范包含调色板、全针、勾边和扩展对象，并记录了半针／tent stitch 在不同实现中的存放差异与时间相关调整。[S07]

Ursa 文档说明 Cross Stitch Saga 已采用 OXS。[S06] 但这不等于：

- 可以把 `.oxs` 改后缀为 `.saga`。
- 所有 OXS 扩展都能无损导入 Saga。
- 所有版本之间的符号、股数和针法行为相同。

首期目标应是“经过指定 Saga 版本实测的 OXS”，而不是未验证的原生 `.saga` 导出。

## 4. 知识系统与规则引擎

### 4.1 四层知识结构

| 层级 | 内容 | 建议实现 |
|---|---|---|
| 材料知识 | 绣线、品牌、系列、线号、色值来源、绣布、CT | 结构化数据库与版本化目录 |
| 针法知识 | 几何、方向、股数、落针位置、图例 | 数据模型、渲染器、校验器、测试夹具 |
| 设计与生产规则 | 配色约束、碎色、针法范围、格式限制 | 可执行规则引擎 |
| 设计经验 | 背景取舍、眼睛与轮廓保护、优秀修改案例 | 文档检索、案例库、专家标注 |

知识系统不应仅由文档向量检索组成。需要逐针执行和校验的内容，应进入结构化数据或代码规则。

### 4.2 规则的三种性质

| 类型 | 示例 | 系统行为 |
|---|---|---|
| 硬规则 | 越界、无效配方、错误尺寸、未处理的识别未知项 | 阻止发布或明确失败 |
| 软规则 | 孤立针偏多、颜色过碎、少量使用的颜色较多 | 给出问题区域和优化建议 |
| 审美判断 | 删除哪些背景、表情是否改变、轮廓是否准确 | AI 提案，用户或设计师确认 |

孤立针可能是瞳孔、高光或星星，因此“孤立针必须删除”不能成为无条件硬规则。难度阈值是产品策略，不应宣传为行业统一标准。

### 4.3 规则记录结构

```text
rule_id
name
rule_type：hard / soft / aesthetic
applicable_conditions
severity
parameters
source_reference
rule_version
allowed_exceptions
suggested_actions
test_cases
```

结构化规则不应依赖大模型实时回忆。AI 可以解释规则和提出参数建议，但参数生效前必须经过范围校验。

### 4.4 规则示例

| 规则 ID | 内容 | 类型 |
|---|---|---|
| `GEOMETRY_BOUNDS` | 针脚和落针点必须位于允许范围 | 硬规则 |
| `RECIPE_EXISTS` | 使用的配方和材料必须可解析 | 硬规则 |
| `LEGEND_COMPLETE` | 所有已使用用线都能由图例解释 | 硬规则 |
| `NO_UNRESOLVED_CELLS` | 发布版本不能包含未确认的识别格 | 硬规则 |
| `NO_SILENT_EXPORT_LOSS` | 导出不得静默丢弃不支持内容 | 硬规则 |
| `LOCKED_REGION_UNCHANGED` | 未经确认不得修改锁定区域 | 硬规则 |
| `CONFETTI_WARNING` | 小连通域和孤立针超出当前策略阈值 | 软规则 |
| `LOW_USAGE_COLOR` | 个别颜色使用量很低，建议检查是否合并 | 软规则 |
| `SUBJECT_IDENTITY_REVIEW` | 简化后主体辨识度或表情存在疑问 | 审美判断 |

重叠规则必须按针法定义：勾边覆盖全针可能合理，不能规定“任何两个针脚都不得重叠”。

## 5. 统一针脚数据模型

### 5.1 唯一可信主数据：PatternDocument

内部定义自己的 `PatternDocument`，而不是将 PDF、RGB 图片或某个外部格式直接作为数据库模型。

```text
                         PatternDocument
                                |
              +-----------------+-----------------+
              |                 |                 |
          图纸与图例        针脚效果预览        材料与统计
              |
       PDF / OXS / 其他格式适配器
```

要求：同一发布版本的全部交付物必须能追溯到同一份针脚数据。

### 5.2 建议模块

| 模块 | 内容 |
|---|---|
| `metadata` | 作品、作者、来源、使用授权记录、版本 |
| `fabric` | 布类型、标称密度、有效针数密度、底色、留边 |
| `grid` | 横纵格数、原点、坐标方向、占用边界 |
| `materials` | 品牌、系列、线号、色值来源与目录版本 |
| `thread_recipes` | 单色或混线的组成和股数 |
| `full_stitches` | 全针矩阵，明确区分留空与有针 |
| `fractional_stitches` | 分数针的类型、位置、方向、配方 |
| `backstitches` | 独立线段集合与配方 |
| `ornaments` | 法国结、珠绣等扩展对象 |
| `regions_and_locks` | 主体、背景、关键细节与锁定范围 |
| `legend` | 图层、符号与用线配方映射 |
| `uncertainty` | 逆向识别的不确定格、线段、图例及候选 |
| `provenance` | AI 提案、人工修改、参数、规则和模型版本 |

### 5.3 坐标与几何约定

建议明确以下内部约定，并在每个导入导出适配器中转换：

```text
原点：左上角。
X：向右增长。
Y：向下增长。
全针格坐标：0 ≤ col < width，0 ≤ row < height。
网格顶点：位于格子的边界，不等同于格子索引。
```

分数针和勾边可使用整数子网格表示。例如 `subgrid_scale = 2` 时，一格对应两单位，半格位置也能使用整数，避免浮点坐标误差。

以格子 `(col, row)` 为例：

```text
左上角：(2*col,     2*row)
右下角：(2*col + 2, 2*row + 2)
格中心：(2*col + 1, 2*row + 1)
```

这是内部设计建议，不是对 OXS 等外部格式坐标的声明。特殊针法超出当前表达能力时，应扩展模型或拒绝该功能，不应近似写入而不告知用户。

### 5.4 用线配方设计

建议将股数放在配方组成中，使不同针法复用材料身份，但保持各自的用线方式。

```json
{
  "material": {
    "id": "thread_dmc_310",
    "brand": "DMC",
    "series": "Mouline Special",
    "code": "310",
    "display_srgb": null,
    "color_source": null,
    "calibration_status": "unverified"
  },
  "recipes": [
    {
      "id": "recipe_1",
      "components": [{"material_id": "thread_dmc_310", "strands": 2}]
    },
    {
      "id": "recipe_2",
      "components": [{"material_id": "thread_dmc_310", "strands": 1}]
    }
  ]
}
```

该片段仅演示结构，不是完整 JSON Schema，也不提供已校准色值。完整 Schema 需要另行定义字段约束、迁移策略和扩展命名空间。

混线以多个 `components` 表达。配方中的材料引用必须存在，股数必须为合法正整数。

### 5.5 留空与识别未知不能混用

建议全针层使用“整数配方索引矩阵 + 独立不确定性图层”：

```text
0：已确认留空。
正整数：对应版本内的有效配方索引。
uncertainty：尚未确认的格子及其候选解释。
```

对于识别未知位置，即使底层矩阵暂存 0，也不能将其解释为已确认留空。编辑器应突出标记，发布校验必须阻止带未知项的正式图纸。

还可以将识别草稿与已确认 `PatternDocument` 分离，只有通过确认的数据才能进入发布模型。

### 5.6 存储与扩展

全针矩阵适合压缩块或数组存储，不建议每一针都创建一行业务数据库记录。勾边和装饰适合对象数组。

需要版本化保存：数据模型、材料目录、规则集、计算参数、随机种子（适用时）、模型输出和人工确认。只保存提示词不足以复现一次 AI 建议。

<a id="s06"></a>
## 6. 图片正向打版流程

### 6.1 总体流程

```text
上传原图
  → 输入分析与约束收集
  → 主体／背景区域规划
  → 分割、裁切与人工修正
  → 目标网格上的画面简化
  → 真实线色受限配色
  → 可绣性优化
  → 可选的针法与轮廓设计
  → AI／人工审核
  → 结构校验与发布
  → 图纸、预览、材料表与交换文件
```

### 6.2 输入约束

建议用户可配置：绣布与 CT、目标物理尺寸或网格规模、颜色预算、允许针法、期望难度、背景保留程度、绣布底色和留边。

并非全部字段都必须让初学者填写。系统可以给出建议，但发布时必须将默认值固定为明确数据，并展示关键假设。

目标尺寸与网格数冲突时，应让用户选择优先约束，不应同时显示互相矛盾的数值。

### 6.3 阶段职责分工

| 阶段 | AI 职责 | 确定性引擎职责 | 中间产物 |
|---|---|---|---|
| 输入分析 | 题材、主体、关键细节、复杂度 | 方向与透明度处理、读取尺寸 | 输入报告 |
| 需求规划 | 尺寸、色数、难度建议 | 约束换算和检查 | 设计配置 |
| 背景处理 | 保留、简化、删除区域判断 | 分割掩膜、裁切、区域编辑 | 区域图与掩膜 |
| 画面简化 | 判断应保留的纹理与特征 | 降噪、局部调整、网格采样 | 简化候选 |
| 配色 | 评价候选并保护特征 | 真实线色选择与网格分配 | 调色板与全针草稿 |
| 可绣性优化 | 判断合色是否破坏关键细节 | 连通域、颜色合并、统计 | 优化草稿与差异 |
| 针法设计 | 建议勾边与特殊针法 | 生成几何、检查材料和格式范围 | 多图层针脚 |
| 审核交付 | 对比原图和针脚预览 | 规则校验、统计、排版、导出 | 发布版本 |

### 6.4 主体与背景：三层区域策略

建议分为：

```text
必须保留 / 可以简化 / 可以删除
```

例如猫坐在窗台上，猫是主体；窗框可能支撑构图；窗外细碎树叶可以大量简化。因此“去背景”不应默认等于“只剩抠出的物体”。

技术上可采用“视觉语言模型分析语义 + 分割模型生成掩膜”。SAM 2 提供提示式图像分割和自动掩膜能力，可作为候选组件，但需使用本项目素材评测。[S10]

用户必须可以修正掩膜并锁定区域。默认保留原图；涉及重新生成、改动人物表情或物体形状的操作，应单独确认。

### 6.5 必须在目标网格上评价细节

大图清晰不代表缩成针格后仍然清楚。眼睛缩小后不足一格时，仅对原图锐化不能解决表达能力不足。

系统应比较：增加网格数、扩大主体占比、简化局部形状，或在允许时引入勾边。

建议生成三个候选方向：

| 方向 | 主要目标 | 应展示的比较信息 |
|---|---|---|
| 简易 | 更少颜色、更少碎色、更大形状 | 实际尺寸、色数、针数、难度指标 |
| 均衡 | 辨识度与操作负担平衡 | 同上 |
| 细节 | 保留更多结构与层次 | 同上，并提示增加的成本 |

这些是设计方向，不应预先承诺某个固定颜色数适合所有图片。

### 6.6 真实线色受限配色

配色目标不只是平均色差最小。还应考虑主体辨识度、轮廓、颜色预算、局部碎色和操作负担。

Lab 与 CIEDE2000 可用于色差计算；Colour 官方文档提供相应实现。[S11] 但效果取决于输入颜色和绣线色库的质量，不能代替实物校验。

建议流程：

```text
准备有来源的线色候选库
  → 依据区域重要性选择候选色
  → 在颜色预算内分配网格用线
  → 计算局部碎色和关键区域误差
  → 提出区域合色或保留建议
  → 用户确认后提交
```

对眼睛、鼻子、文字等区域采用更强保护；天空、墙面等区域允许更积极合色。初学者模式建议默认关闭容易产生密集散点的抖动配色，将其作为进阶选项。

### 6.7 AI 提交操作提案，而不是几万格 JSON

用户输入：“减少天空里的碎色，但不要改变猫的眼睛。”

系统应得到受约束的修改提案：

```text
目标区域：天空。
操作：合并局部近似颜色。
保护区域：猫眼。
限制：保持主要明暗结构，不修改锁定区域。
执行后：展示影响颜色、针数、差异区域与可撤销操作。
```

提案需要绑定输入版本，由程序执行并校验。AI 不应直接承担逐格枚举、材料汇总、精确排版或文件编码。

<a id="s07"></a>
## 7. 可绣性与质量评价

### 7.1 不采用单一“AI 总评分”

建议同时报告结构正确性、图纸可读性、操作负担和视觉质量。不同层级不能互相替代。

| 维度 | 建议指标／检查项 | 解释 |
|---|---|---|
| 结构 | 越界、配方引用、几何冲突、未知项、图例完整性 | 硬性正确性 |
| 视觉 | 主体辨识度、关键区域差异、轮廓保留、颜色近似 | AI／人工结合 |
| 碎色 | 孤立针数量、小连通域占比、低使用量颜色 | 启发式指标，不是绝对错误 |
| 操作负担 | 局部颜色数、颜色区域分散程度、估计跨区负担 | 不等于确定的实际走线或工时 |
| 可读性 | 符号混淆、字号、网格、分页、重叠区 | 打印和屏幕实测 |
| 材料 | 配方、针法数量、用量估算与假设 | 需要试绣校准 |
| 兼容性 | 目标应用、版本、格式和功能组合 | 必须独立验证 |

### 7.2 碎色与关键细节保护

建议以连通区域分析识别孤立针和小色块，并区分背景区域与关键区域。连通性使用 4 邻域还是 8 邻域，应写入指标定义，避免同名指标含义不同。

“减少碎色”不应机械地将全部小区域删除；应以局部差异预览说明收益与代价。瞳孔、高光、纽扣或星星等可能只有一针，但语义价值很高。

### 7.3 用量与时间估算

建议输出分项数量、估算范围、假设和校准版本。起收针、跨区走线、废线与个人习惯会影响结果。

首版可以提供基于针脚数量与布密度的保守估算，但不应声称已计算出唯一最优走线路径。材料采购取整与安全余量属于另一层明确配置。

<a id="s08"></a>
## 8. 逆向工程流程

### 8.1 先判断输入类型

| 类型 | 优先技术路线 | 输出可信度 |
|---|---|---|
| 结构化 OXS 等 | 解析文件与语义转换 | 已支持字段可逐项核对 |
| 含文字／矢量对象的 PDF | 提取符号、坐标、网格、图例和线段 | 可较精确恢复，但需校验 |
| 扫描／拍摄图纸 | 图像矫正、网格识别、符号聚类、图例关联 | 必须保留不确定项 |
| 成品照片／AI 效果图 | 图像理解与重新打版 | 近似重建，不是唯一答案恢复 |

### 8.2 结构化文件导入

导入时检查格式版本、尺寸、材料、配方、针法和扩展字段。对不支持的内容，应返回明确报告，允许中止或经确认转换；不得默认忽略。

自有模型与外部格式存在不同表达能力时，应记录损失清单。格式的成功解析不等于完成无损转换。

### 8.3 PDF 与扫描图纸恢复

对包含可提取文本与矢量对象的 PDF，优先使用已有结构；只有缺少可用结构时才进入图像识别流程。

```text
定位图纸区域
  → 透视／旋转校正
  → 识别网格、坐标与页面关系
  → 分离格内符号、线条和装饰
  → 聚类相同符号
  → 读取并关联本图纸的图例
  → 恢复针脚与配方
  → 多页拼接、重叠去重
  → 标出冲突和不确定区域
  → 人工确认与结构校验
```

必须依据该图纸自己的图例建立符号关系。不能认为同一个符号在所有图纸中都代表相同颜色。

### 8.4 置信度与误差处理

以 40,000 格图纸为例，99.9% 的格子正确率仍可能意味着约 40 个错误格。平均准确率不能替代关键区域确认。

建议记录：格子识别置信度、候选符号、线号映射置信度、线段检测置信度、页面拼接冲突、人工确认状态。

若页面重叠区域出现不同结果，应保留冲突并要求确认，而不是任意覆盖。

### 8.5 成品参考重建

成品照片受光照、相机颜色、布料纹理与拍摄角度影响；不同线号和针法可能产生相近图像。因此建议命名为“成品参考重建”或“图片再打版”。

输出说明需区分：用户提供的尺寸／材料、从照片推定的结构、系统重新设计的配色／针法，以及仍不确定的部分。

AI 效果图中的毛发、高光或细线若没有对应的可行针脚，应进行删减或重新设计，不能直接进入正式图纸。

<a id="s09"></a>
## 9. 系统架构与模块职责

### 9.1 推荐架构

首期采用“模块化后端 + 异步计算任务 + 独立编辑器”，不急于拆成大量微服务或复杂多智能体系统。

```text
Web 工作台
    |
业务 API ───────── 项目／版本／任务元数据
    |
任务编排层 ─────── 异步计算 Worker
    |                    |
    |        +-----------+-----------+
    |        |                       |
    |    确定性图案引擎          AI 服务适配层
    |        |                       |
    |    材料／规则服务          模型与提示模板
    |        |
    +──── 对象存储：原图、掩膜、工程、预览、导出物
```

### 9.2 模块职责

| 模块 | 责任 | 不应承担的职责 |
|---|---|---|
| Web 编辑器 | 画布、图层、图例、锁定、修改对比、撤销 | 自行维护另一套无法核对的作品真相 |
| 业务 API | 用户、项目、版本、访问权限、任务与发布 | 长时间阻塞执行全部图像计算 |
| 图案引擎 | 网格、配色、几何、统计、可绣性分析、渲染 | 依赖模型猜测针数或材料汇总 |
| AI 适配层 | 图像分析、区域判断、方案评价、操作提案 | 绕过锁定和硬规则直接发布 |
| 任务编排层 | 阶段依赖、缓存、重试、取消、状态 | 隐藏中间产物与失败原因 |
| 材料／规则服务 | 目录版本、来源、规则配置、知识检索 | 将未校准色值标为实测事实 |
| 导出适配器 | PDF、OXS、目标软件配置与损失报告 | 静默抛弃不支持内容 |
| 存储层 | 元数据、版本、原图和产物 | 用文件名代替完整版本关联 |

### 9.3 建议技术基线

以下为架构建议，不是已经确认的选型；依赖版本、授权和部署条件需在实施阶段确认。

| 层级 | 建议 |
|---|---|
| 图案引擎 | Python 独立包，可离线运行、测试和批处理 |
| API | Django／DRF 或 FastAPI 二选一，不必同时引入 |
| 前端 | React／TypeScript；Canvas 或 WebGL 画布 |
| 任务 | 选择支持依赖、重试、取消和阶段缓存的任务系统 |
| 元数据 | PostgreSQL 等关系型数据库 |
| 大型产物 | 对象存储，保存原图、掩膜、矩阵、工程和导出文件 |
| AI 调用 | 可替换的模型适配器与版本化提示模板 |

前端不建议给每个针格创建一个独立 DOM 节点。需要平移缩放、视口裁剪、局部刷新，并分层绘制底色、针脚、符号、网格和问题标记。

### 9.4 建议代码模块边界

```text
pattern_core/       数据模型、坐标、配方、Schema 迁移
image_pipeline/     输入处理、区域、采样与简化
palette_engine/     色库、色差、配色和合色
stitch_engine/      针脚生成与几何操作
quality_engine/     硬规则、碎色、质量报告
pattern_renderer/   针脚预览、图层渲染
format_adapters/    OXS、PDF 与其他导入导出
ai_assistant/       图像分析、提案与审阅接口
workflow/           阶段依赖、版本、缓存和重试
api/                业务接口
editor/             Web 工作台
tests/              单元、回归、格式和验收样例
```

目录只是职责示意，可按现有仓库规范调整。图案引擎和文件适配器应能在没有 AI 服务连接的情况下完成基础工作。

<a id="s10"></a>
## 10. 编辑器与人机协作

### 10.1 编辑器是核心交付能力

首版至少提供：原图对照、区域掩膜修正、区域锁定、逐针改色、颜色合并、同色高亮、问题定位、前后对比、撤销与重做。

建议三类视图：

| 视图 | 目的 |
|---|---|
| 原图／简化图 | 判断构图与主体保留 |
| 针脚预览 | 查看由真实针脚生成的效果 |
| 图纸视图 | 检查符号、坐标、网格和局部可读性 |

需要提供按线号、配方、针法和问题类型过滤的能力，减少人工查错负担。

### 10.2 三个主要确认点

```text
主体与背景处理后
  → 候选图纸选择后
  → 最终导出前
```

已确认主体应形成锁定或保护约束，后续全图合色不得悄悄改变它。

### 10.3 自然语言与明确编辑操作共用接口

自然语言修改应调用与人工编辑相同的操作接口，例如：

```text
merge_colors
replace_recipe
set_cell
lock_region
unlock_region
simplify_region
add_backstitch（后续阶段）
```

AI 提案至少包含：基础版本、目标区域、操作参数、保护条件、预期影响和原因说明。执行前做参数校验，执行后计算差异；用户可以拒绝和撤销。

不能仅提供“重新生成整张图”，否则局部改善可能导致其他区域退化。

<a id="s11"></a>
## 11. 任务、版本与发布机制

### 11.1 中间产物与阶段记录

每阶段建议保存：

```text
输入产物引用与内容摘要
输入版本
阶段名称
参数与规则版本
模型版本及原始建议（适用时）
输出产物
质量指标
人工确认状态
错误、重试与耗时记录
```

任务缓存应考虑输入内容、参数、规则／色库／引擎版本。改变色库后不能复用只按原图哈希命中的旧配色结果。

### 11.2 局部重算

用户只修改背景时，优先重算背景及受其影响的统计和导出。若全局调色板需要改变，必须检查是否影响锁定主体，并提示冲突。

局部计算不代表可以只更新一张预览图；作品整体的统计、图例和材料表仍需重新核对。

### 11.3 发布版本不可变

发布时固定：针脚数据、材料目录版本、配方、图例、绣布配置、规则报告、导出配置与所有交付物关联。

发布后再修改，生成新版本，不能覆盖旧版中的某个文件而保留其他旧文件。

建议每个交付包附带清单：项目 ID、版本 ID、生成日期、格式、相关文件及内容哈希，防止“新封面配旧图纸”。

### 11.4 工作流状态与验证状态分开

工作流可表示为：

```text
DRAFT → PROCESSING → REVIEW_REQUIRED → APPROVED → PUBLISHED
```

任务失败或取消是任务状态，不应把最近一个有效设计版本破坏掉。

验证状态是独立证据，不应压缩成一个“已验证”标签：

```text
结构检查：未执行／通过／失败
目标软件导入：未验证／通过／存在损失
设计师审核：未审核／通过／需修改
关键区域试绣：未试绣／通过／需修改
```

首版可允许发布结构检查通过、但尚未试绣的用户设计，前提是明确标识状态。不能将“结构检查通过”显示为“实绣验证通过”。

<a id="s12"></a>
## 12. 导出与兼容性设计

### 12.1 导出配置独立于作品数据

同一个 `PatternDocument` 可以使用不同导出配置：

```text
print_color
print_bw
pattern_keeper_pdf
oxs_target_profile
```

符号、页边距、单格尺寸、分页和重叠区域属于展示配置；实际用线与针脚属于设计数据，不能因打印设置而改变。

### 12.2 PDF 排版检查

建议逐项检查：

- 页码、图案网格大小、行列坐标和中心定位正确。
- 10×10 网格与普通格线有清晰层级。
- 符号大小与实际打印尺度匹配，相似符号足够可区分。
- 彩色与黑白模式都能独立读懂。
- 分页重叠区和拼接方向清晰，重复展示的针不被重复统计。
- 图例包含品牌、系列、线号、配方／股数和针法含义。
- 预览页、图例页和图纸页不因布局误导目标阅读软件。
- 字体授权、嵌入和符号映射经过验证，不依赖未说明的本机字体。

对 Pattern Keeper 的导出配置，以官方说明和目标版本实测为依据。[S08]

### 12.3 导出损失策略

当格式不能保留某些内容时，返回机器可读与用户可读的损失报告，至少包含：对象、问题、影响、建议处理和确认状态。

可采用三种结果：

```text
SUCCESS：目标能力范围内完整导出。
SUCCESS_WITH_CONFIRMED_LOSS：用户明确确认损失后导出。
BLOCKED：存在不允许或未确认的损失。
```

不能在无提示情况下将混线替换成单线、删除勾边、忽略特殊针法，或丢弃未知线号。

### 12.4 兼容矩阵

| 目标应用 | 应用版本 | 格式／配置 | 全针 | 勾边 | 分数针 | 配方／股数 | 状态 |
|---|---|---|---|---|---|---|---|
| Pattern Keeper | 实测时填写 | 目标 PDF 配置 | 待验证 | 待验证 | 待验证 | 待验证 | 未验证 |
| Cross Stitch Saga | 实测时填写 | OXS 配置 | 待验证 | 待验证 | 待验证 | 待验证 | 未验证 |
| 其他指定软件 | 按需求选择 | 对应适配器 | 待验证 | 待验证 | 待验证 | 待验证 | 未验证 |

表中是测试计划，不表示这些应用一定支持所有列出的功能。每次验证应保存测试文件、截图、差异与应用版本。

## 13. MVP 范围与研发路线

### 13.1 推荐 MVP

定位：**AI 辅助的全针十字绣打版工作台**。

以下是首版研发约束建议，不是行业标准：

| 项目 | 建议范围 |
|---|---|
| 输入 | JPG／PNG；基础 OXS 导入用于验证和继续编辑 |
| 优先题材 | 插画、宠物、主体明确的简单场景 |
| 网格规模 | 初始以长边约 300 格以内建立性能与质量基线 |
| 材料 | 一个经过整理、注明来源并逐步校准的 DMC 纯色棉线目录 |
| 针法 | 正式输出先支持全针；模型预留勾边和其他针法 |
| AI | 主体分析、背景简化、候选参数、局部修改建议 |
| 编辑 | 区域保护、逐针改色、合色、撤销与对照 |
| 输出 | 针脚预览、彩色／黑白 PDF、OXS、材料表、自有工程 |
| 验证 | 硬规则检查、指定目标软件测试、选取代表区域试绣 |

首版不同时承担：照片级人像高保真、所有专有格式、任意扫描图纸恢复、全部高级针法和无人审核自动发布。

### 13.2 研发阶段与退出条件

| 阶段 | 主要任务 | 退出条件 |
|---|---|---|
| M0：知识与格式验证 | 领域词典、Schema、材料目录结构、手工测试图、PDF／OXS 出口 | 已知针脚可以正确导出、打开并逐项核对 |
| M1：确定性打版 | 网格采样、真实线色映射、碎色分析、编辑器 | 不依赖 AI 也能完成一份可编辑图纸 |
| M2：AI 辅助设计 | 语义区域、背景简化、多方案、局部提案 | 相比 M1 减少人工修改，不破坏锁定内容 |
| M3：实绣闭环 | 打版师审核、试绣、材料估算校准、发布状态 | 有真实样本证明图纸与针脚预览一致 |
| M4：逆向与高级针法 | 扫描识别、勾边、分数针、混线、更多格式 | 各功能独立完成精度、几何与兼容验收 |

建议先增加勾边，再逐步加入分数针、混线和复杂扫描图纸。基础 OXS 导入属于早期互操作验证，不必等到完整逆向模块。

### 13.3 不应颠倒的实施顺序

```text
已知针脚 → 数据校验 → 可读图纸 → 软件导入 → 实际试绣
                           |
                           ↓
                 图片转换与 AI 辅助自动化
```

先验证最小交付链路，再提高自动化比例。否则容易得到漂亮的展示系统，却无法保证针脚和图纸真实可用。

## 14. 测试、验收与实绣闭环

### 14.1 四层验收

| 层级 | 主要检查 | 最低要求 |
|---|---|---|
| 结构正确 | 几何、配方、留空、股数、图例、未知项、统计 | 所有适用硬规则通过 |
| 软件兼容 | 在指定应用版本中实际打开并核对 | 不存在未告知的尺寸、颜色或针法差异 |
| 图纸可读 | 实际打印、符号、网格、分页与图例 | 无需依赖颜色也能正确辨认黑白图纸 |
| 实际可绣 | 专家审核与关键区域试绣 | 标记并修复影响实际操作的设计问题 |

不能只用自己编写的导入器验证自己编写的导出器，因为两者可能共享相同错误。外部应用核对与独立样例同样必要。

### 14.2 最小测试夹具

建议先手工构造小图案，预先写出期望针脚与材料统计：

| 样例 | 验证目标 |
|---|---|
| 单色矩形 | 网格尺寸、边界、全针数、成品尺寸 |
| 棋盘格 | 配色、坐标方向、符号映射 |
| 留空与白线并存 | 留空语义、背景渲染、针数区别 |
| 文字与单针高光 | 关键细节保护、孤立针例外 |
| 非对称图案 | 检查镜像、转置、原点与方向错误 |
| 多页图案 | 页码、拼接、重叠展示与计数去重 |
| 勾边覆盖全针 | 分层渲染和合法叠加，扩展阶段启用 |
| 分数针方向集 | 角点、中心、方向和格式差异，扩展阶段启用 |
| 未知符号图纸 | 识别不确定性、人工确认和发布阻断 |
| 锁定区域修改 | 局部操作不会改变受保护内容 |

### 14.3 回归评测集

从第一天积累经过授权的原图、人工图纸、模型建议、人工修改和试绣反馈。优先用于回归评测，不必立即训练专用大模型。

建议覆盖：宠物、人物、插画、风景、文字、大面积留白、渐变、细线、高对比边界和复杂背景，并分别统计不同题材的表现。

评价 AI 的主要方式是对比人工修订量、关键细节保留和可绣性，而不是仅由另一个模型给一个分数。

### 14.4 试绣闭环

```text
选择代表性区域
  → 打版师审核
  → 实际按图绣制
  → 记录材料、耗时、操作困难和修改
  → 对照针脚预览
  → 更新规则／估算／评测样例
```

优先测试眼睛、渐变、深浅交界、留白、细线轮廓和碎色区域。若照片用于效果比对，应记录拍摄条件，避免将光照差异直接归因于线号错误。

### 14.5 发布门禁示例

```text
[必须] Schema 和几何校验通过。
[必须] 所有材料与配方可解析。
[必须] 不存在未解决的识别未知项。
[必须] 图例、针脚与材料统计一致。
[必须] 锁定区域未被未经确认的操作改动。
[必须] 导出不存在未确认损失。
[必须] 全部交付物绑定同一发布版本。
[展示] 指定软件实测状态。
[展示] 设计师审核状态。
[展示] 试绣范围与结论。
```

## 15. 风险与待验证事项

### 15.1 关键风险

| 风险 | 典型后果 | 应对 |
|---|---|---|
| 只优化视觉相似度 | 碎色多、操作复杂、实际不愿意绣 | 引入区域与可绣性目标，保留人工审核 |
| AI 改变主体 | 表情、外形或关键细节失真 | 原图保留、区域锁定、差异确认 |
| 色库来源不可靠 | 屏幕好看但实物偏色、线号不可用 | 来源版本、实体色卡、逐步校准 |
| 特殊针法表示不足 | 预览可见但无法落针或导出 | 分层几何、材料适配规则、功能门禁 |
| 外部格式差异 | 尺寸、方向、股数或针法损失 | 独立适配器、兼容矩阵、损失报告 |
| 逆向识别过度自信 | 少数错误格破坏整幅作品 | 置信度、关键区域检查、人工确认 |
| 预览与图纸不同源 | 宣传效果无法照图复现 | 同一 PatternDocument 生成全部产物 |
| 用量与工时过度精确 | 采购不足或完成时间误导 | 输出范围与假设，用试绣反馈校准 |
| 文件输入与访问风险 | 恶意文件、资源耗尽、跨项目泄漏 | 类型／大小限制、解析隔离、资源限额、权限检查 |
| 上传内容与第三方模型 | 隐私或素材使用范围不明确 | 明确告知数据用途、删除机制和对外发送范围 |

文件安全、隐私和素材授权属于开发检查项，不代表已完成适用法律或许可审查。

### 15.2 开发前需要确认的事项

1. **色库资料与许可：** 真实线号目录来自哪里，屏幕色值是否可用，授权范围及实体校准如何进行。
2. **目标软件：** 首批要兼容哪些应用与具体版本，哪些针法必须支持。
3. **产品用户：** 更偏普通用户还是打版师；二者对默认难度、编辑器深度与审核流程的要求不同。
4. **MVP 限制：** 网格上限、颜色预算、图片大小、单任务资源和可接受交互性能。
5. **材料默认值：** 首批支持的绣布、CT、股数与留边建议，以及默认值的确认方式。
6. **实绣资源：** 由谁审核与试绣，如何保存反馈，如何校准估算。
7. **专有格式：** 是否确需原生 SAGA 等出口，是否有合法可用规范与独立测试样例。
8. **上传与导入权限：** 用户素材、商用图纸、案例库和模型训练数据的使用边界。

这些是实施待办，不应在需求文档中被默认标记为已经解决。

## 17. 术语表

| 术语 | 本项目中的含义 |
|---|---|
| 打版 | 将视觉设计转换为针脚、配方、图例和操作说明 |
| 可绣性 | 在指定材料、针法和难度约束下可以真实操作的程度 |
| CT | 绣布密度标识，需结合布类型解释 |
| 有效针数密度 | 换算后的每英寸针数，用于物理尺寸计算 |
| 股数 | 实际同时使用的绣线股数 |
| 全针 | 一个完整的 X 型针脚 |
| 分数针 | 半针、四分之一针、四分之三针等表达 |
| 勾边 | 以线段表现轮廓等细节的针法 |
| 碎色／Confetti | 局部出现较多分散的小色块或孤立针的现象 |
| 线色／材料 | 可采购的品牌、系列与线号身份 |
| 用线配方 | 一种或多种线号及各自股数的组合 |
| 图例 | 解释符号、用线、针法和股数的说明 |
| 针脚预览 | 从真实针脚数据渲染的设计效果，不是自由生成图片 |
| PatternDocument | 本系统唯一可信、版本化的作品数据模型 |
| 导出配置 | 面向打印或特定软件的排版与格式设置 |
| 格式损失 | 转换后无法保留的语义、对象或展示信息 |
| 试绣 | 按图实际绣制，用于验证操作与效果 |
| 成品参考重建 | 依据成品图像重新设计，不承诺恢复唯一原图纸 |

## 最终开发原则

> 先证明“明确的针脚数据 → 可读图纸 → 目标软件正确打开 → 按图试绣 → 与针脚预览一致”这条链路成立，再用 AI 提高主体取舍、配色与局部修订的效率。
>
> 项目的核心价值不是把图片做得像刺绣，而是将必要的视觉细节转换为真实的针和线，同时清楚说明复杂度、取舍与验证程度。
